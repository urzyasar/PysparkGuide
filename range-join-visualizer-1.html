CASES How many buckets get trusted vs scanned — depends on bucket size vs window size
0 full buckets
Window smaller than one bucket
e.g. 5-min buckets, 1-min trade window. start_bucket = end_bucket most of the time — the whole window sits inside one bucket. There is nothing to trust, every row must be scanned. The bucket trick gives zero savings here; it degrades to a plain filter on one bucket.
0 full buckets, 2 touched
Window straddles one bucket edge
Same small window, but it happens to cross a bucket boundary — e.g. window ends just after a bucket starts. start_bucket ≠ end_bucket, yet end_bucket − start_bucket − 1 = 0. Both touched buckets are boundary buckets — still nothing "fully inside," both get row-scanned.
2+ full buckets
Window wider than several buckets
e.g. 1-min buckets, 5-min window. Buckets strictly between the start and end edge are entirely swallowed by the window — every row in them satisfies BETWEEN start_time AND end_time automatically, since the bucket's own time range is a subset of the window's. Trust their pre-agg, skip scanning them.
Configure bucket size and trade start/end above — this panel will highlight which case your current setup falls into.
IMPLEMENTATION Full working SQL — copy/paste into Spark SQL
-- Step 0: pre-aggregate market_data into fixed-size buckets, once CREATE TABLE market_data_buckets AS SELECT sym, FLOOR(transaction_time_us / :bucket_size_us) AS bucket_id, COUNT(*) AS bucket_count, MIN(price) AS bucket_min, MAX(price) AS bucket_max, MIN_BY(price, transaction_time_us) AS bucket_first_price, MIN_BY(transaction_time_us, transaction_time_us) AS bucket_first_ts FROM market_data GROUP BY sym, FLOOR(transaction_time_us / :bucket_size_us); -- Step 1: derive each trade's touched bucket range WITH trade_buckets AS ( SELECT t.trade_id, t.sym, t.start_time_us, t.end_time_us, FLOOR(t.start_time_us / :bucket_size_us) AS start_bucket, FLOOR(t.end_time_us / :bucket_size_us) AS end_bucket FROM trades t ), -- Step 2: buckets strictly between the edges — trust pre-agg, no row scan full_agg AS ( SELECT tb.trade_id, SUM(b.bucket_count) AS full_count, MIN(b.bucket_min) AS full_min, MAX(b.bucket_max) AS full_max, MIN_BY(b.bucket_first_price, b.bucket_first_ts) AS full_first_price FROM trade_buckets tb JOIN market_data_buckets b ON b.sym = tb.sym AND b.bucket_id > tb.start_bucket AND b.bucket_id < tb.end_bucket GROUP BY tb.trade_id ), -- Step 3: only the two edge buckets — exact row-level BETWEEN filter boundary_agg AS ( SELECT tb.trade_id, COUNT(*) AS boundary_count, MIN(m.price) AS boundary_min, MAX(m.price) AS boundary_max, MIN_BY(m.price, m.transaction_time_us) AS boundary_first_price FROM trade_buckets tb JOIN market_data m ON m.sym = tb.sym AND FLOOR(m.transaction_time_us / :bucket_size_us) IN (tb.start_bucket, tb.end_bucket) AND m.transaction_time_us BETWEEN tb.start_time_us AND tb.end_time_us GROUP BY tb.trade_id ) -- Step 4: combine — existence falls out of row_count for free SELECT tb.trade_id, COALESCE(f.full_count,0) + COALESCE(b.boundary_count,0) AS row_count, LEAST(f.full_min, b.boundary_min) AS min_price, GREATEST(f.full_max, b.boundary_max) AS max_price, CASE WHEN COALESCE(f.full_count,0)+COALESCE(b.boundary_count,0) = 0 THEN 'NO_MARKET_DATA' ELSE 'MATCHED' END AS marker FROM trade_buckets tb LEFT JOIN full_agg f ON f.trade_id = tb.trade_id LEFT JOIN boundary_agg b ON b.trade_id = tb.trade_id;
Bucket size is your one tuning knob — pick it as roughly typical trade duration ÷ 10–50, so most trades land in several full buckets plus 2 boundary buckets rather than being all-boundary (see Case 1/2 above).

TRY IT Work it out by hand before checking
Given: bucket_size = 45s, trade window 09:02:10 → 09:06:40.

Before running it — work out:
  1. start_bucket = FLOOR(seconds-from-09:00 ÷ 45)
  2. end_bucket = FLOOR(seconds-from-09:00 ÷ 45)
  3. how many full buckets sit strictly between them?
Fill in your three answers, then hit Check.
Hint — how to get seconds from clock time
09:02:10 is 2 minutes 10 seconds past 09:00:00 → 130 seconds.
09:06:40 is 6 minutes 40 seconds past 09:00:00 → 400 seconds.

Then apply FLOOR(seconds / bucket_size) to each, exactly like Stage 1 does in the visualizer above. Full buckets = end_bucket − start_bucket − 1.

IMPLEMENTATION Full working SQL — copy/paste into Spark SQL
-- Step 0: diagnose which key is hot SELECT sym, COUNT(*) AS cnt FROM market_data GROUP BY sym ORDER BY cnt DESC; -- Step 1: salt only the hot sym's rows on the LARGE side CREATE OR REPLACE TEMP VIEW market_data_salted AS SELECT *, CASE WHEN sym IN (:hot_syms) THEN sym || '_' || CAST(FLOOR(RAND()*:N) AS INT) ELSE sym END AS salted_sym FROM market_data; -- Step 2: explode the SMALL side — one row per salt value, hot syms only CREATE OR REPLACE TEMP VIEW trades_salted AS SELECT t.*, CASE WHEN t.sym IN (:hot_syms) THEN t.sym || '_' || salt.value ELSE t.sym END AS salted_sym FROM trades t LEFT JOIN (SELECT EXPLODE(SEQUENCE(0, :N-1)) AS value) salt ON t.sym IN (:hot_syms); -- Step 3: join on the SALTED key, then GROUP BY trade_id — this recombines the N shards SELECT ts.trade_id, COUNT(*) AS row_count, MIN(md.price) AS min_price, MAX(md.price) AS max_price, MIN_BY(md.price, md.transaction_time) AS first_price FROM trades_salted ts JOIN market_data_salted md ON md.salted_sym = ts.salted_sym AND md.transaction_time BETWEEN ts.start_time AND ts.end_time GROUP BY ts.trade_id; -- NOT salted_sym — grouping by trade_id merges the shards back
Only hot keys get salted — salting every key would fragment already-small partitions and add shuffle overhead for no benefit. Pick N so hot_count / N lands near your other partitions' size.
